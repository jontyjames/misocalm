# MisoCalm App Audit - 2026-06-24

This audit is the working map for the cleanup and launch-readiness phase. It is based on the current codebase, `UX-PHILOSOPHY.md`, `SACRED-GEOMETRY.md`, `MISOCALM-AGENTS.md`, and the graphify report.

## Executive Summary

MisoCalm has a strong emotional and technical core: Supabase auth, onboarding, dashboard, journal, six guided experiences, premium plumbing, PWA shell, and basic AI chat infrastructure already exist. The app is not just a sketch anymore.

The main issue is consistency. Some flows feel polished and sanctuary-like; others still show unfinished surfaces, generic loading states, oversized files, or operational gaps. The next phase should not add broad new features. It should make every existing path feel calm, fast, trustworthy, and app-store ready.

## Current Strengths

- Clear product soul: the UX and sacred geometry documents give the app a real design constitution.
- Core practice suite exists: Alive, Focus, Grounding, Impermanence, Mandala, and Pulse are implemented.
- Journal ecosystem exists: logging, saved entries, deeper processing, insights, and trigger patterns are present.
- Auth and premium paths exist: Supabase auth, PremiumGate, Stripe checkout, portal, and subscription plumbing are wired.
- PWA foundation exists: manifest, service worker, offline page, install banner, and Capacitor config are present.
- Baseline test harness exists: Vitest now covers the important hooks and UI primitives.
- Graph visibility exists: graphify identifies core hubs, hyperedges, and fragile architecture zones.

## High Priority Risks

1. Loading and route transitions are not yet consistently calm.
   Recent work replaced many generic spinners with shaped skeletons, but the welcome/auth entry, debug views, and some internal components still need review. The app should preserve page shape while loading wherever possible.

2. Soundscapes are not built.
   There is still a soundscapes route and soundscape constants. The product must not imply this is ready until it is either hidden, reframed as coming soon, or built properly.

3. MisoAI is not yet the game-changing companion.
   Basic chat plumbing exists, but the real product needs retrieval from the misophonia research/course material, safe mode selection, crisis boundaries, memory rules, and in-app action suggestions.

4. App-store readiness is incomplete.
   Capacitor config exists, but native iOS/Android projects, store screenshots, review/demo flows, privacy forms, native build checks, and payment policy decisions still need a dedicated track.

5. Platform risk needs a real mobile pass.
   The codebase contains many `min-h-screen` patterns, some fixed overlays, service worker caching, canvas experiences, and PWA lifecycle behavior that need iOS Safari and Android Chrome QA.

6. Stripe production operations are not ready locally.
   The build warns that `STRIPE_WEBHOOK_SECRET` is missing. Webhook delivery and production env parity need verification before launch.

7. Oversized files will slow future work.
   `src/lib/educationData.js`, `src/lib/constants.js`, `app/globals.css`, debug analytics, several experience components, and some onboarding pages exceed or approach the project size limits.

8. Flow Lab is useful but not yet intuitive.
   It currently helps inspect loaders and scenarios, but it does not yet feel like a clear "play every path" rehearsal tool. Treat it as internal scaffolding, not product.

## MisoAI Direction

MisoAI should be the central companion, not a generic chat box. The best first version should support three modes:

- Triggered now: short, grounding, under 30 seconds to help.
- Preparing for a sound: practical plan, boundaries, and self-advocacy.
- Processing afterward: validation, pattern reflection, and one gentle next step.

The context layer should come from profile, severity, selected triggers, recent logs, practice history, course stage, and curated research/course chunks. It needs strict boundaries: no medical diagnosis, no therapy claims, crisis escalation when needed, and no hidden pressure loops.
